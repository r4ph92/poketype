# Implementation milestones

This is a delivery order, not permission to omit later school requirements. Track evidence against each requirement ID. Each milestone should leave a runnable application.

## 1. Foundation and real guest race

Inspect workspace; choose compatible packages and hosting-compatible transport. Scaffold required stack, database/migrations/seed, env example, shared pixel tokens/components and basic locale/theme support. Implement guest identity, public room creation/join, authoritative host start, same exercise for two human browsers, live top-down progress and results. Implement tested scoring/error-mode domain contracts early. No simulated opponents passed off as multiplayer.

Exit: two browser contexts complete one real race and see consistent settled results; local setup documented.

## 2. Complete essential room and typing behavior

All three room types, fullest eligible public matchmaking, one-use invitations, host settings, French/English sentence and shuffled-word exercises, repeated characters, uppercase/digits/symbols, both error modes. Countdown, duration/inactivity/safety endings, reconnect, abandon/spectator, leave, room closure and same-group rematch. Visible corrected ranking and discreet overtakes. Handle more than the four mockup players within a documented measured capacity.

Exit: lifecycle and authorization E2E tests plus text validation/scoring unit coverage pass.

## 3. Accounts, persistence and learning statistics

Username/password, GitHub and Discord setup, signup guest-history transfer, permanent history/detail and WPM trends with condition filters. Guest session statistics and honest no-recovery messaging. Complete light/dark and responsive non-race pages. Add account/profile states from visual guide.

Exit: persistence survives restart; account ownership isolation and atomic guest transfer verified. External OAuth credentials may be a clearly reported manual integration step, never silently mocked in the finished UI.

## 4. Pokémon creative loop and polished screens

Starter choice, collection selection, racer bound at race start, XP ledger, random drops, evolution and celebration. Implement dashboard, PC collection, outdoor lobby and results/reward UI against references. Add reward/no-reward/duplicate/evolution states. A development seed demonstrates progression rapidly without changing normal rules.

Exit: reward replay tests pass, collection persists for accounts, guest conversion carries progression, all five screens visually inspected.

## 5. Remaining features and delivery

Desirable: avatar import/upload, realistic bots and keyboard heatmap. Lower priority: remember-me, host transfer, optional bonus mode with explicit rules, milestones/notifications. Keep all unfinished items visible rather than declaring full compliance. Bonus-mode metrics remain separate from classic records.

Finish GitHub CI with unit/E2E coverage, tested production build, setup/deploy documentation for AWS or Vercel topology and HTTPS, asset manifest, limitations and requirement completion report. Deploy only when actually authorized/configured. Source Q1–Q13 remain tracked until answered.
